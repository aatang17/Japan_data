Using the Data From Your AI Assistant

The complete manual for Plover Analytics' MCP server: setup, what it carries, every lookup it offers, how to read a response, and what to do when something looks wrong.

What this is

This site publishes its data over the Model Context Protocol (MCP) — an open standard that lets an AI assistant such as Claude look data up from an external source while you chat with it. You add one URL to your assistant; after that, questions about Japanese statistics and Japanese company filings are answered from this site's numbers rather than from the assistant's memory.

The assistant does the reading and writing. The server only answers data lookups, and it can only see what this site already publishes: the same figures, from the same accepted release, computed by the same code as the public API. Nothing you ask is used to change anything here — every lookup is read-only.

Getting connected

The connect URL is:

https://ploveranalytics.com/mcp

claude.ai and Claude Desktop

  1. Open Settings → Connectors (a paid Claude plan is required for custom connectors).
  2. Choose Add custom connector, name it Plover Analytics, paste the URL, and add it. No authentication is asked for — there is none.
  3. Start a new chat and confirm the connector is enabled in the tools menu under the message box. Connectors added mid-chat are often not picked up until a new conversation.

Claude Code (terminal)

claude mcp add --transport http plover-analytics https://ploveranalytics.com/mcp

Run it once; every new session then has the tools. claude mcp list should show the server as connected.

Codex (terminal)

codex mcp add plover-analytics --url https://ploveranalytics.com/mcp

Cursor and VS Code

Both register a URL scheme for installing an MCP server, so a link does the whole job — the editor opens and asks you to confirm: Add to Cursor · Add to VS Code. The link carries nothing but the name and the URL above.

Everything else

Any client that supports remote MCP servers (Streamable HTTP transport) takes the same URL. The server is stateless, needs no key, and identifies itself as Plover Analytics.

What the server carries

Twenty-five datasets in twelve sections — Japanese official statistics on one side, company disclosures filed on EDINET on the other. The datasets directory lists them in full with sources and update schedules.

  • Prices — cpi-jp (categories: headline, the cores, the ten major expenditure groups) and cpi-jp-items (full item depth, including the 582 individually priced items), monthly from January 1970 on the 2020 base.
  • Monetary — boj-assets: the Bank of Japan's principal balance-sheet items as end-of-month stocks and during-month flows, in ¥100 million, from July 1996. Flows go negative; a negative JGB net flow is balance-sheet run-off.
  • Rates — jgb-yields: constant-maturity JGB yields for 15 maturities, every business day since September 1974. Yields can be negative.
  • Tourism — jnto-visitors (arrivals by market from 2003; the two latest months are estimates) and accommodation-jp (guest nights and occupancy by prefecture from 2011, with a definition change in January 2026).
  • Demography — population-jp and population-jp-municipal (Basic Resident Register counts by prefecture and by municipality) and population-jp-history (the long run from 1975).
  • Trade — trade-semis and trade-inputs: monthly customs exports and imports of semiconductors, equipment and silicon wafers by partner country, from 2001.
  • Agriculture — agri-prices, rice-prices-jp, rice-inventory-jp, rice-production-cost and ja-statistics.
  • Ownership — cross-shareholdings (policy holdings both directions, from FY2021), shareholder-register (top-ten holders and the investor-category split) and large-shareholdings (the 5% tape).
  • Governance — boards-and-pay (every director as filed, officer remuneration, individually disclosed pay) and agm-votes (each proposal's result and each director's own approval percentage).
  • Capital returns — buybacks: authorisation, monthly execution, unspent balance and cancellation.
  • Assets — facilities: disclosed sites with book value by asset class, land area, and the rental-property note.
  • Financials — financials (statements as filed plus calculated ratios) and segments (revenue by region, named customers, reportable segments).

Bank-level financial statements (jba-banks) and the FSA bad-loan and bank earnings series are built but not yet published on this server; the assistant is not shown tools it cannot answer with.

The lookups, one by one

You never call these yourself — the assistant chooses them from your plain-English question. Knowing what exists tells you what you can ask. Eight generic lookups cover every dataset.

  • List datasets — every dataset with its section, shape (series, company or events), what it covers and which lookups apply. The assistant uses it to orient itself.
    Ask: “What data do you have on Japan?”
  • Describe a dataset — one dataset's full card: source and credit line, every measure with its trust label and, for calculated ones, its formula, the screens it offers, and what this server actually holds of it.
    Ask: “Where does the rice price data come from, and how far back does it go?”
  • Search — a company by Japanese or English name or securities code, or a data series by name or code, across every dataset. Company hits list the datasets that know the company; series hits return the code the history lookup needs.
    Ask: “Is there a series for mobile phone charges?”
  • Get a company — one company by securities code. With a dataset named, the full view from it (holdings, register, board and pay, buybacks, facilities, financials, AGM votes). Without one, a compact profile across every dataset that knows the company, plus a list of those that do not.
    Ask: “What do you have on 7203?”
  • Get series history — up to six series of a series-shaped dataset, as the published value or as a year-over-year, month-over-month or 3-month annualized rate, over any window.
    Ask: “Rice prices year-over-year since 2022.”
  • Ranked screen — a ranked cross-section from a dataset's own screens: oldest boards, largest unspent buybacks, cheapest land per m², lowest director approval, highest ROE, widest gender pay gap.
    Ask: “Which companies have the oldest boards?”
  • List peer groups — the groups a company can be compared within: the TOPIX scale bands (Core30, Large70, Mid400, Small), the JPX segments (Prime, Standard, Growth) and the 33- and 17-industry classifications.
  • Compare within a peer group — one metric across one peer group, ranked, with the group's median and quartiles, and optionally one company's rank and percentile inside it. Companies that do not report the metric are excluded and listed with the reason — never counted as zero.
    Ask: “Is Toyota's ROE normal for a Core30 company?”

Two more sit alongside them. Check a published figure reconciles a number you have seen in the press against what the filings say, on the stated basis. And the dataset cards are readable as MCP resources, so a client can load them without spending a lookup.

The original per-dataset lookups — inflation overview, contributions to headline, inflation breadth, cross-shareholding coverage, unwind ranking, the boards-and-pay and financials tools, arrivals, the yield curve and the BOJ balance sheet — remain available for compatibility, and the assistant may still choose them. They answer with the same numbers as the generic lookups.

How to read what comes back

Every lookup result carries the same disclosure fields. If you ever need to check the assistant's statement, these are what to look at:

  • trust — official means the figure is exactly as published by the source — an index level, a yield, a filed share count or book value. calculated means this platform computed it from official inputs.
  • calc — for every calculated figure, the exact formula used. A rate computed from published (rounded) indices can differ from the source's own published rate by up to ±0.1 pp; the Methodology page explains why.
  • cite — a permanent URL on this site showing the same view. Click it to see the numbers the assistant saw. This is the link to quote in a note or a post.
  • as_of_release / latest_period — which release answered the lookup. A figure is always “as of” a named period.
  • as_of — most lookups take a date and answer as the data stood on it, from the stored vintage history. That is how you see a number as it was before a revision, or a filing-derived screen as it looked before later filings arrived.
  • Missing values come back as missing, never as zero. If the assistant tells you a number is unavailable, that is the data speaking, not a failure.
  • Coverage (filing datasets) — extraction status and filer counts ride along with every response drawn from EDINET filings. “¥21tn across 125 filers extracted so far” is honest; “Japan's cross-shareholdings total ¥21tn” is not, and the data says so.

Ten questions to try

  1. What are Japan's headline, core, and core-core inflation rates right now?
  2. Break the current headline rate into percentage-point contributions by group.
  3. What share of individually priced items is rising more than 2%, and how does that compare with two years ago?
  4. How much JGB did the Bank of Japan buy last month, net of redemptions?
  5. Chart the 10-year JGB yield against the 30-year over the last three years.
  6. Which visitor markets grew fastest last month, and how full were the hotels in Kyoto?
  7. Who holds 8306 as a policy shareholding, and what reasons do the filers state?
  8. Which directors got the lowest approval at last season's AGMs?
  9. Show me 7203's financial statements as filed, then its ROE against its Core30 peers.
  10. What did the latest CPI month look like as of the day before it was revised?

Limits, honestly stated

  • Japan only, and not every Japanese statistic. No wages, GDP or producer prices yet; no Tokyo advance, regional or seasonally adjusted CPI; no yen price levels from the CPI (an index says rice rose 30%, not that it costs ¥3,000). Bank-level statements and the FSA bad-loan series are built but not yet published here. The coverage grows dataset by dataset.
  • Filing datasets are not the whole market. They accumulate filing by filing from EDINET, and several start at FY2025 or later. Every aggregate comes back with its own coverage denominator — quote the denominator with the number.
  • Never mix measure types. Index levels, yen levels, stocks and flows are different things; the server labels which is which and they are never ranked or summed together.
  • History windows are trimmed. Long histories return the most recent points within a size budget; the assistant can page through older windows by asking with explicit dates. Up to six series per history lookup.
  • Rate limit. Roughly 120 lookups per minute per connection — far more than a conversation uses. Bulk work belongs on the public API.
  • The assistant's prose is its own. This server hands over numbers with labels and links. Interpretation, forecasts, and causal stories are the product of whichever AI you connect — this site publishes none of those. Check anything you plan to quote against its cite link.

When something looks wrong

  • The connector won't add — custom connectors need a paid Claude plan; free accounts can't add them.
  • The tools don't appear — start a new chat (web/desktop) or a new session (Claude Code); check the connector is enabled in the chat's tools menu.
  • “Rate limit exceeded” — wait a minute. If a single question routinely trips it, the assistant is looping; rephrase more narrowly.
  • The assistant's rate differs slightly from an official publication — expected within ±0.1 pp; see Methodology → Calculations. Index levels should never differ; if one does, that is a bug — please report it.
  • A lookup answers “not published yet” — the server you're connected to doesn't carry that dataset yet. List datasets shows what it does carry.
  • A number with no cite link, or a claim you can't reproduce — treat it as the assistant's own words, not this site's data.

For data teams

The endpoint speaks JSON-RPC 2.0 over a single stateless POST — no session, no authentication, gzip supported. A minimal round-trip:

curl -X POST https://ploveranalytics.com/mcp -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Tool results return the same JSON the site's public API serves, plus the disclosure fields above. For scheduled or bulk retrieval, use the REST API directly — it is the same data with proper HTTP caching.
